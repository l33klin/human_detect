# 两个性能实验的共同协议

基线：`main` 的 `2775693606e0d7fe7810702eb9568afde9f81580`。两个分支保留相同的基准工具，不改动 main。

## 实验一：跟踪与身份特征降频

分支 `experiment/temporal-tracking`。模型、阈值、预处理和身份库与原版相同，仅视频时序策略不同。静态图片仍逐张完整推理。每 5 帧或 0.5 秒强制完整检测；中间帧使用下采样图像上的稀疏光流估计位移。低质量跟踪、场景切换、明显人脸外观变化会触发完整检测。身份特征最多复用 1 秒，复用结果必须附带来源和年龄。身份库变更后清空缓存。每路流独立状态。

对照：相同输入帧，原版每帧完整推理。检验平均/P95 耗时、TPU 各阶段调用次数、相对基线的人体/人脸框 IoU、身份输出差异。速度收益同时报告结果变化，不能用减少检测次数掩盖丢失或错误身份。

## 实验二：检测模型联合编译

分支 `experiment/cocompile`。只有编译策略变化，所有帧完整推理，不启用跟踪或身份缓存。

两个检测模型均从 Coral 原始量化模型重新编译：单独编译为控制组，按人体优先、人脸优先两种顺序联合编译为处理组。编译器版本、输入 SHA-256、编译日志、输出 SHA-256 固定并保存。保持原 MobileFaceNet 身份模型不变。

当前身份模型来源只提供已编译文件，没有同一权重的原始量化模型。因此只能验证两检测模型联合编译的效果，不能把结果称为三模型联合编译。额外测量“人体→人脸”的循环与完整“人体→人脸→身份”循环，以揭示独立身份模型对共享缓存收益的影响。

## 输入、测量和限制

- 服务器 `pn41`，同一块 `/dev/apex_0`，单进程串行推理，无 CPU 神经网络回退。
- 公开源图来自 Coral 固定提交：`grace_hopper.bmp` 和 `face.jpg`；仅内存读取，源数据及每段输入帧均记录 SHA-256。
- 合成静止、平移、脸部遮挡、源图切换/空白以及两图多人拼接五种序列；尺寸 512×600、1280×720、1920×1080。场景键 `two_people` 是两图拼接的历史名称，不表示恰好两人；`face.jpg` 本身包含多人，实际数量保留在逐帧结果中。
- 这是对公开静态图的几何合成，尺寸变化含缩放/拉伸；不是这些分辨率的真实拍摄数据，不测真实识别准确率、自然运动或 RTSP 解码性能。
- 身份库只录入 reference 图；输出与逐帧基线比较，基线不是人工标注真值。
- 每个组合预热 5 帧，跟踪实验测量 40 帧，联合编译实验测量 20 帧，均重复 3 次；每个实验内部变体的输入帧完全一致，两个实验分别与自己的基线比较。联合编译另有每组合 100 次、3 轮的固定调用微基准。每次随机化变体顺序，固定随机种子 20261020。OpenCV 限定单线程，减少服务器争用。
- 不限制处理 FPS；跟踪的时间间隔使用 25 FPS 源时间戳，测量时不 sleep。
- 单独统计 pipeline 外层处理耗时以及各模型 detect/embed 的耗时/次数；含预处理和后处理，不含下载、帧生成、网络或视频解码。
- 保存逐帧输出供审计，并生成相对基线的汇总。P95 使用 NumPy percentile；硬件繁忙、温度和其他服务会引入噪声，因此同时保留重复测量。

运行：

```bash
PYTHONPATH=. python -m experiments.benchmark --variant baseline=models --temporal \
  --output results/temporal.json
PYTHONPATH=. python -m experiments.compare results/temporal.json \
  --output results/temporal-summary.json
```

第二分支不使用 `--temporal`，而是通过重复 `--variant 名称=模型目录` 比较编译变体。

参考：[Coral 参数缓存与联合编译](https://www.coral.withgoogle.com/docs/edgetpu/compiler/#co-compiling-multiple-models)。
