# 实验二结果：两检测模型联合编译

2026-10-20，pn41，单块 PCIe TPU。完整 pipeline 基准版本 `36211c6`。
四种变体各 900 帧，共 3,600 帧；每组合 20 帧、3 轮，预热 5 帧，变体顺序随机化。
另外固定调用微基准每组合执行 100 次、3 轮。所有模型神经网络计算都在 TPU，只有检测反量化和框后处理位于 CPU。

## 缓存分配与解释

两种联合编译输入顺序在本次编译器日志中产生相同分配：

| 编译方式/模型 | 片上参数缓存 | 片外参数流式读取 |
| --- | --- | --- |
| 单独/人体 | 4.89 MiB | 0 |
| 单独/人脸 | 7.61 MiB | 192.81 KiB |
| 联合/人体 | 1.90 MiB | 2.90 MiB |
| 联合/人脸 | 5.60 MiB | 1.92 MiB |

两个检测模型连续交替运行时，共享缓存减少切换成本；加入未共同编译的身份模型后，该优势基本消失。多人场景连续多次运行同一检测模型时，联合模型较小的片上缓存需要更多片外参数读取，与观测到的耗时增加一致。这是结合编译日志和受控微基准的解释。

遮挡导致部分帧不调用身份模型时，联合编译可能仍有收益；不能将这种局部收益推广为完整身份识别链路提速。

## 输出变化和结论

各处理组相对原预编译基线：额外正身份 0，缺失正身份 0，成功配对人脸的身份差异 0。框和人数逐帧差异保留在原始记录及统计中。

当前两模型联合编译没有带来稳定的完整链路提升，多人场景反而更慢，因此不推荐替换默认模型。同一权重的 MobileFaceNet 原始量化模型未提供，三模型共同编译效果仍未验证；实验只回答当前可获取模型的两检测联合方案。27 项测试本地和服务器通过，最终基准正常退出。
